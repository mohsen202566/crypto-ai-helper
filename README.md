# ربات اسکن چندارزی (Multi-Symbol Scoring Bot)

ربات معاملاتی که هم‌زمان ۳۰+ ارز را روی تایم‌فریم ۱۵ دقیقه اسکن می‌کند، به هر
کدام امتیاز می‌دهد، و فقط روی بالاترین امتیازها پوزیشن باز می‌کند — هر پوزیشن
مستقل، ایزوله، و با حد ضرر و حد سود از همان لحظهٔ ورود.

## چه چیزی نسبت به نسخهٔ قبل عوض شد

| قبل | حالا |
|---|---|
| فقط یک ارز (DOGE) | حداقل ۳۰ ارز، انتخاب خودکار بر پایهٔ حجم |
| ورود پله‌ای / مارتینگل | یک ورود، یک حد ضرر، یک حد سود |
| شرط‌های دودویی (همه باید تأیید کنند) | امتیاز وزن‌دار ۰ تا ۱۰۰ |
| یک پوزیشن در لحظه | ۱ تا ۳۰ پوزیشن هم‌زمان، قابل تنظیم از تلگرام |
| سود بدون بررسی کارمزد | ورودی که کارمزد سودش را بخورد اصلاً باز نمی‌شود |

## منطق امتیازدهی

هر ارز در هر اسکن دو امتیاز می‌گیرد (لانگ و شورت)، هر کدام میانگین وزن‌دار سه بخش:

| بخش | وزن | چه می‌سنجد |
|---|---|---|
| روند | ۳۵٪ | جایگاه قیمت نسبت به EMA50/EMA200، شیب EMA، تأیید تایم‌فریم ۱ ساعته |
| مومنتوم | ۴۰٪ | RSI و کراس خروج از اشباع، کراس هیستوگرام MACD |
| حجم | ۲۵٪ | حجم کندل نسبت به میانگین ۲۰ کندل، جهت بدنهٔ کندل |

ورود فقط وقتی انجام می‌شود که:
1. امتیاز از آستانه (پیش‌فرض ۸۰) بالاتر باشد،
2. امتیاز جهت مخالف بالا نباشد (بازار مبهم نباشد)،
3. بازار رنج نباشد (نسبت کارایی کافمن بالای ۰.۲۵)،
4. **سود مورد انتظار بعد از کارمزد و اسلیپیج، حداقل ۲.۵ برابر خود هزینه باشد.**

اگر چند ارز هم‌زمان سیگنال بدهند، بالاترین امتیاز اسلات را می‌گیرد.

## خروج

- **حد سود**: فاصلهٔ حد ضرر × نسبت ریسک/سود (پیش‌فرض ۱ به ۲)
- **حد ضرر**: بر پایهٔ ATR واقعی همان ارز (نه درصد ثابت) — ارز پرنوسان استاپ دورتر
- **برگشت مومنتوم**: خروج زودهنگام اگر پوزیشن در سود باشد و جهت کاملاً برگردد
- **پایان مهلت**: پوزیشن راکد بعد از ۸ ساعت بسته می‌شود تا اسلات آزاد شود

اگر حد سود و حد ضرر در یک کندل هر دو لمس شوند، محافظه‌کارانه حد ضرر فرض می‌شود.

## نصب روی سرور

```bash
mkdir -p /root/staged-bot && cd /root/staged-bot
# فایل‌های پروژه را اینجا کپی کنید
pip install -r requirements.txt --break-system-packages

cp .env.example .env
nano .env          # کلیدها را وارد کنید
chmod 600 .env     # فقط root بتواند بخواند
```

## اجرای دائمی با systemd

```bash
cp staged-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable staged-bot
systemctl start staged-bot
```

بررسی وضعیت و لاگ:
```bash
systemctl status staged-bot
journalctl -u staged-bot -f
```

## دستورات تلگرام

| دستور | کار |
|---|---|
| `پنل` | پنل ترید واقعی (موجودی، سرمایهٔ درگیر، PnL) |
| `ترید مجازی` | پنل ترید مجازی |
| `پوزیشن` | جزئیات پوزیشن‌های باز |
| `پوزیشن ۵` | حداکثر پوزیشن هم‌زمان (۱ تا ۳۰) |
| `امتیاز ۸۰` | آستانهٔ ورود (۵۵ تا ۹۵) |
| `اهرم ۵` | سقف لوریج (۱ تا ۱۰) |
| `سقف ۵۰` | سقف سرمایهٔ درگیر (۰ = کل موجودی) |
| `ارزها` | فهرست ارزهای تحت اسکن |
| `چرا` | دلیل اینکه چرا الان وارد نمی‌شود |
| `آمار` | آمار کامل، واقعی و مجازی جدا |
| `ترید فعال` / `ترید خاموش` | روشن و خاموش کردن ترید واقعی |
| `وضعیت` | سلامت سیستم |

## مدیریت سرمایه

سرمایه **همیشه زنده** از صرافی خوانده می‌شود، نه عدد ثابت.

- مجموع مارجین همهٔ پوزیشن‌های باز از ۶۰٪ موجودی بیشتر نمی‌شود.
- سرمایهٔ مجاز بین اسلات‌ها پخش می‌شود: با «پوزیشن ۱۰»، هر پوزیشن یک‌دهم بودجه.
- لوریج خودکار انتخاب می‌شود: **کم‌ریسک‌ترین** لوریجی که هنوز بعد از کارمزد صرف کند.
- حد ضرر همیشه حداقل ۲ برابر زودتر از لیکوئید فعال می‌شود.

### چند پوزیشن هم‌زمان بهتر است؟

عدد بالا (مثلاً ۲۰) یعنی سرمایه پخش‌تر و ریسک هر معامله کمتر، ولی هر پوزیشن
آن‌قدر کوچک می‌شود که ممکن است کارمزد سودش را بخورد — در آن حالت ربات خودش
ورود را رد می‌کند و در «چرا» دلیلش را می‌گوید. عدد پایین (۲ تا ۵) یعنی فقط
بهترین سیگنال‌ها، ولی نوسان حساب بیشتر. با سرمایهٔ کم، عدد پایین منطقی‌تر است.

## هشدار

هیچ استراتژی‌ای سود را تضمین نمی‌کند و این ربات هم نمی‌کند. کاری که می‌کند این
است که ریسک را *محدود و شفاف* کند: هر معامله حد ضرر دارد، نسبت ریسک به سود از
قبل مشخص است، و ورودی که بعد از کارمزد صرف نکند اصلاً باز نمی‌شود.

با نسبت ۱ به ۲، حتی نرخ برد ۴۰٪ هم بلندمدت مثبت می‌ماند — ولی این «بلندمدت»
است، نه هر روز. حتماً هفته‌ها در حالت مجازی اجرا کنید و آمار واقعی را ببینید
قبل از اینکه `ترید فعال` بزنید.

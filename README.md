# ربات اسکن چندارزی — Momentum Ignition

ربات معاملاتی که هم‌زمان ده‌ها ارز را روی تایم‌فریم ۱ ساعته اسکن می‌کند و
پامپ/دامپ‌های واقعی (حرکت شدید + حجم بالا) را دنبال می‌کند — نه اینکه
برخلافشان وارد شود. هر پوزیشن مستقل و ایزوله است، با حد ضرر اولیه از همان
لحظهٔ ورود و استاپ دنبال‌کننده (trailing stop) به‌جای حد سود ثابت.

## چرا این استراتژی

نتیجهٔ بک‌تست روی دادهٔ واقعی توبیت: سه ایدهٔ mean-reversion (فید کردن
حرکت‌های اخیر — liquidity sweep، volatility squeeze، funding-rate reversal)
همگی رد شدند. ایدهٔ momentum (دنبال کردن حرکت، نه برخلافش) روی ۱، ۷، ۱۰ و ۳۰
روز و روی ده‌ها تا صدها ارز به‌طور پایدار سودده بود. پارامترهای پیش‌فرض
(`پامپ ۸٪`, `ضریب حجم ۱.۵×`, `تریل ۲٪`) نتیجهٔ همان بهینه‌سازی‌اند.

## منطق سیگنال

هر ارز در هر اسکن این‌طور بررسی می‌شود:

1. **پنجرهٔ پامپ** — آخرین ۶ کندل (`PUMP_WINDOW_BARS`) چند درصد حرکت کرده؟
   اگر حداقل `پامپ ۸٪` (`PUMP_THRESHOLD_PCT`) بود، کاندید پامپ/دامپ است.
2. **تأیید حجم** — حجم همان پنجره باید حداقل `ضریب حجم ۱.۵×` میانگین ۲۰
   کندل باشد؛ وگرنه رد می‌شود. این تأیید که پول واقعی وارد شده، نه نویز.
3. **تأیید ادامهٔ حرکت** — قیمت لحظه‌ای باید فراتر از بستهٔ کندل سیگنال رفته
   باشد (یعنی حرکت هنوز ادامه دارد، برنگشته).

اگر چند ارز هم‌زمان سیگنال بدهند، شدیدترین حرکت اسلات را می‌گیرد.

## خروج — حد ضرر اولیه + استاپ دنبال‌کننده

- **حد ضرر اولیه**: درصد ثابت از قیمت ورود (`INITIAL_STOP_PCT`، پیش‌فرض ۴٪).
- **استاپ دنبال‌کننده**: با رشد قیمت به نفع پوزیشن، استاپ به فاصلهٔ `تریل ۲٪`
  از بهترین قیمت ثبت‌شده دنبالش می‌آید — ولی هرگز عقب نمی‌رود. برخلاف حد سود
  ثابت، این باعث می‌شود در یک حرکت پارابولیک بخش بزرگ‌تری از سود گرفته شود.
- **پایان مهلت**: اگر بعد از ۷۲ کندل (`MAX_HOLD_BARS`، حدود ۳ روز روی
  تایم‌فریم ۱ ساعته) نه استاپ و نه تریل خورده باشد، پوزیشن بسته می‌شود.

هر بار که قیمت چک می‌شود (هر چند ثانیه)، بهترین قیمت و استاپ فعال در
دیتابیس ذخیره می‌شوند — با ری‌استارت ربات پیشرفت تریل از دست نمی‌رود.

## نصب روی سرور

```bash
mkdir -p /root/staged-bot && cd /root/staged-bot
# فایل‌های پروژه را اینجا کپی کنید
pip install -r requirements.txt --break-system-packages

cp .env.example .env
nano .env          # کلیدها را وارد کنید
chmod 600 .env     # فقط root بتواند بخواند
```

## اجرای دائمی با systemd

```bash
cp staged-bot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable staged-bot
systemctl start staged-bot
```

بررسی وضعیت و لاگ:
```bash
systemctl status staged-bot
journalctl -u staged-bot -f
```

| `امروز` | خلاصهٔ معاملات امروز |

| `آمار` | آمار کامل، واقعی و مجازی جدا |

## چه چیزی در تلگرام می‌آید

هم در حالت واقعی و هم مجازی، این پیام‌ها خودکار ارسال می‌شوند:

1. **پنل سیگنال** — لحظهٔ باز شدن هر پوزیشن: ارز، لانگ/شورت، قیمت ورود،
   حد ضرر اولیه، لوریج، دلار مارجین، و شدت حرکتی که سیگنال را ساخته.
2. **گزارش لحظه‌ای** — هر ۱۵ دقیقه (قابل تنظیم): سود/زیان تحقق‌نیافتهٔ هر
   پوزیشن، فاصلهٔ استاپ فعال، بهترین قیمت ثبت‌شده، و عمر پوزیشن.
3. **پنل نتیجه** — لحظهٔ بسته شدن، به‌صورت ریپلای روی پیام سیگنال: با استاپ
   دنبال‌کننده بسته شد یا حد ضرر یا پایان مهلت، درصد حرکت قیمت، و سود/زیان
   خالص بعد از کسر کارمزد.
4. **خلاصهٔ روزانه** — تعداد معاملات، نرخ برد، تفکیک استاپ دنبال‌کننده و حد
   ضرر، و مجموع کارمزد.

همهٔ این‌ها در آمار هم ثبت می‌شوند؛ با `آمار` تفکیک واقعی و مجازی را می‌بینید.

## مدیریت سرمایه

سرمایه **همیشه زنده** از صرافی خوانده می‌شود، نه عدد ثابت.

- مجموع مارجین همهٔ پوزیشن‌های باز از ۶۰٪ موجودی بیشتر نمی‌شود.
- سرمایهٔ مجاز بین اسلات‌ها پخش می‌شود: با «پوزیشن ۱۰»، هر پوزیشن یک‌دهم بودجه.
- **اندازهٔ هر پوزیشن**: `دلار ۱۰` یعنی هر پوزیشن دقیقاً ۱۰ دلار مارجین می‌گیرد —
  نه کمتر، نه بیشتر. اگر موجودی آزاد کمتر از این باشد، پوزیشن **باز نمی‌شود**
  (به‌جای اینکه نصفه باز شود). با `دلار ۰` برمی‌گردد به تقسیم خودکار سرمایه.
- **لوریج**: `اهرم ۱۰` یعنی همهٔ پوزیشن‌ها با ۱۰x باز می‌شوند. ربات خودش عوضش نمی‌کند.
  اگر با آن لوریج فاصلهٔ لیکوئید به حد ضرر نزدیک شود، ورود رد می‌شود و دلیلش
  در «چرا» می‌آید.
- حد ضرر همیشه حداقل ۲ برابر زودتر از لیکوئید فعال می‌شود. اگر لوریج انتخابی این
  شرط را نقض کند، ورود رد می‌شود — به همین دلیل لوریج‌های خیلی بالا معمولاً
  خودشان کنار گذاشته می‌شوند.

### چند پوزیشن هم‌زمان بهتر است؟

عدد بالا (مثلاً ۲۰) یعنی سرمایه پخش‌تر و ریسک هر معامله کمتر، ولی هر پوزیشن
آن‌قدر کوچک می‌شود که ممکن است کارمزد ریسکش را ببلعد — در آن حالت ربات خودش
ورود را رد می‌کند و در «چرا» دلیلش را می‌گوید. عدد پایین (۲ تا ۵) یعنی فقط
بهترین سیگنال‌ها، ولی نوسان حساب بیشتر. با سرمایهٔ کم، عدد پایین منطقی‌تر است.

## به‌روزرسانی از نسخهٔ قبلی

دیتابیس به‌صورت خودکار مهاجرت می‌کند؛ نیازی به پاک کردن `runtime.db` نیست.
تنظیمات قبلی («امتیاز») دیگر استفاده نمی‌شوند و با پارامترهای جدید («پامپ»،
«ضریب حجم»، «تریل») جایگزین شده‌اند. فقط اگر می‌خواهید آمار استراتژی قبلی
پاک شود، در تلگرام «ریست آمار» و بعد «تأیید ریست» بفرستید.

## هشدار

هیچ استراتژی‌ای سود را تضمین نمی‌کند و این ربات هم نمی‌کند. کاری که می‌کند این
است که ریسک را *محدود و شفاف* کند: هر معامله حد ضرر اولیهٔ مشخص دارد، استاپ
دنبال‌کننده سود بازشده را قفل می‌کند، و ورودی که فاصلهٔ حد ضررش را کارمزد
ببلعد اصلاً باز نمی‌شود.

نتیجهٔ بک‌تست همیشه‌گی نیست — بازار عوض می‌شود. حتماً چند روز/هفته در حالت
مجازی اجرا کنید و آمار واقعی این بازهٔ زمانی را با «آمار» ببینید، قبل از
اینکه `ترید فعال` بزنید.
